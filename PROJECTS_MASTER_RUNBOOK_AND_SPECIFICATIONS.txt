2. PROJECT 1: ASYMMETRIC ENCRYPTION & KEY MANAGEMENT DASHBOARD
====================================================================================================
[Location]
  Directory: D:\project\DLK\Monish -projects\Asymmetric_Encryption_Dashboard
  Entry Point: app.py

[Architectural Overview & Purpose]
  A cryptographic laboratory and operational key management workstation designed to simplify,
  visualize, and safely execute public-key encryption, signature operations, and key pair lifecycle
  management without requiring low-level OpenSSL command-line mastery.

[Core Cryptographic Primitives Supported]
  1. RSA (Rivest-Shamir-Adleman):
     - Configurable moduli: 1024, 2048, 3072, and 4096 bits.
     - Hardened padding scheme: PKCS#1 OAEP (Optimal Asymmetric Encryption Padding) with SHA-256.
     - Prevents chosen-ciphertext attacks and textbook RSA mathematical factorization vulnerabilities.
  2. ECC (Elliptic Curve Cryptography):
     - NIST prime curves supported: P-256 (secp256r1), P-384, and P-521.
     - Provides military-grade resistance with short key lengths (256-bit ECC matches 3072-bit RSA).
     - Employs ECDH (Elliptic Curve Diffie-Hellman) combined with ephemeral symmetric key wrapping.
  3. ElGamal Cryptosystem:
     - Multiplicative cyclic group encryption based on the Discrete Logarithm Problem (DLP).
     - Incorporates random ephemeral session keys per encryption to ensure semantic security.
  4. Rabin Cryptosystem:
     - Asymmetric encryption provably equivalent to integer factorization difficulty.
     - Quadrating residue calculations modulo n = p*q (demonstrative research implementation).

[Key Modules & Code Artifacts]
  - app.py: Streamlit reactive dashboard organizing tabs for Encryption/Decryption, Key Generation,
    Key Export/Import (PEM/Base64), and Interactive Cryptographic Theory documentation.
  - encryption_algorithms.py: Core object-oriented cryptographic engine utilizing `pycryptodome`
    and `cryptography` primitives.

[Working Steps & Usage]
  1. Key Pair Generation:
     - Select target algorithm (RSA, ECC, ElGamal, or Rabin).
     - Specify bit size (e.g., RSA 2048 or ECC SECP256R1) and click "Generate Keys".
     - Download the PEM/Base64 formatted Public Key (.pub) and Private Key (.pem).
  2. Message Encryption:
     - Navigate to "Encrypt/Decrypt" tab.
     - Paste recipient public key, enter plaintext payload.
     - The engine outputs standard Base64 armored ciphertext.
  3. Message Decryption:
     - Paste private key and ciphertext into the Decrypt pane.
     - The engine verifies padding, computes private key exponentiation/scalar multiplication,
       and recovers plaintext.

4. PROJECT 3: AI/ML STATIC THREAT INTELLIGENCE PIPELINE (MALWARE DETECTOR / MERSAL)
====================================================================================================
[Location]
  Directory: D:\project\DLK\Monish -projects\Malware Detector
  Script: malware_detector[dlk_intern].py
  Web Dashboard: http://127.0.0.1:5000

[Architectural Overview & Purpose]
  A high-speed static malware analysis engine and threat intelligence classifier built for Windows
  Portable Executable (PE) binaries. Eliminates the overhead and sandbox evasion vulnerabilities of
  pure dynamic execution by extracting structural, mathematical, and cryptographic indicators from
  unpacked binaries to produce actionable MITRE ATT&CK kill-chain assessments.

[Core Technical Pipeline]
  1. Static Binary Parsing (`pefile`):
     - Parses DOS headers, PE Headers, Optional Headers, Section Headers, and Import Tables.
     - Inspects Import Address Table (IAT) for suspicious Windows API calls correlated with malware:
       VirtualAlloc, VirtualAllocEx, WriteProcessMemory, CreateRemoteThread (Process Injection T1055),
       URLDownloadToFile, WinHttpOpen (Command and Control T1071), RegSetValueEx (Persistence T1547).
  2. Shannon Entropy Computation:
     - Evaluates bit randomness: H(X) = -sum(P(x_i) * log2(P(x_i))) across the entire binary and
       per section (.text, .data, .rsrc).
     - Entropy scores approaching 7.2 - 8.0 bits/byte identify packed, obfuscated, or encrypted payloads
       designed to evade endpoint signatures.
  3. Signature-Based Verification (`yara-python`):
     - Compiles custom rules including EICAR test signatures and suspicious shell invocation strings
       (e.g., powershell.exe -ExecutionPolicy Bypass, cmd.exe /c).
  4. Machine Learning Classifier:
     - Model: Scikit-learn Logistic Regression trained over a 5-dimensional feature vector:
       [global_entropy, suspicious_api_count, high_entropy_sections, yara_hits, size_kb].
     - Output: Continuous risk probability score from 0 to 100.
       * >= 75: MALWARE (Red verdict, immediate quarantine recommendation)
       * 40 - 74: SUSPICIOUS (Yellow verdict, manual triage indicated)
       * < 40: CLEAN (Green verdict, normal executable characteristics)
  5. MITRE ATT&CK Kill Chain Narration:
     - Correlates static detections into narrative attack sequences across Execution, Persistence,
       Defense Evasion, and C2 stages.

[Working Steps & Usage]
  1. Open http://127.0.0.1:5000 in your browser to access the MERSAL interface.
  2. Drag and drop any Windows `.exe` or binary sample into the upload arena.
  3. The backend calculates entropy, parses imports, evaluates YARA rules, and feeds features to the ML model.
  4. View the final risk verdict, section entropy graph, matched threat rules, and MITRE mapping.

[Architectural Overview & Purpose]
  NEMESYS is a distributed, unsupervised Machine Learning Network Intrusion Detection System (NIDS)
  and SOC-style monitoring console. Designed to detect zero-day volumetric anomalies, port scans,
  data exfiltration spikes, and DoS attacks across heterogeneous endpoint nodes without requiring
  pre-labeled threat datasets.

[Architecture & Mechanics]
  1. Distributed Telemetry Capture:
     - `telemetry_agent.py`: High-efficiency, cross-platform telemetry agent utilizing `psutil` and
       `requests` to collect socket connection states, bytes sent/received, packet rates, and protocol counts.
     - `tshark_agent.py`: Raw PCAP stream parser leveraging Wireshark's CLI `tshark` engine for deep
       flow inspection.
  2. Central Ingestion & WebSocket Broadcast (FastAPI - Port 8000):
     - Asynchronous ingestion endpoints (`POST /api/telemetry`) aggregate flows from distributed nodes.
     - Real-time WebSocket channel (`/ws`) broadcasts scored packet metrics to all connected dashboards.
  3. Unsupervised ML Engine (Isolation Forest):
     - Isolates observations by randomly selecting features and splitting values.
     - Anomalies require significantly fewer splits to isolate than normal baseline traffic.
     - Outputs continuous anomaly scores mapped into Severity bands: LOW, MEDIUM, HIGH, and CRITICAL.
  4. Real-Time SOC Dashboard (React + Vite + TailwindCSS - Port 5173):
     - Live throughput graphs (Bits Per Second / Packets Per Second).
